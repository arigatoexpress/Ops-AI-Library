# Project / Pilot Review Checklist

Use before promoting a prompt pack, Gemini agent, SharePoint content, or future automation from “personal experiment” to “team recommended.”

## 1. Purpose

- [ ] Problem is stated in one sentence.  
- [ ] Audience (role) is clear.  
- [ ] Success metric is measurable (time saved, fewer rewrites, clearer handoffs, etc.).

## 2. Data

- [ ] Data classes listed (public / synthetic / internal / confidential).  
- [ ] Tool is approved for that class.  
- [ ] Prompt and examples use scrubbed placeholders only.  
- [ ] “Never paste” list reviewed with author.

## 3. Human in the loop

- [ ] Output is labeled as draft.  
- [ ] Who reviews before share/act is named (role).  
- [ ] Agent cannot take irreversible actions without approval.

## 4. Quality

- [ ] At least 3 realistic scrubbed test cases run.  
- [ ] Failure modes documented (hallucination, over-confident tone, missing owners).  
- [ ] “Needs verification” behavior confirmed.

## 5. Ownership

- [ ] Content owner (human).  
- [ ] Backup owner.  
- [ ] Review date (e.g., 90 days).

## 6. Communication

- [ ] Not presented as official FedEx product or policy.  
- [ ] SharePoint / Teams message uses plain English.  
- [ ] Feedback path defined (what worked / what failed).

## Decision

- [ ] **Approve for team use**  
- [ ] **Pilot only (named users)**  
- [ ] **Hold — needs changes**
